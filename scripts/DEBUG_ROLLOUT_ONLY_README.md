# Debug Rollout Only 原理说明

## 架构：Miles 如何起 SGLang

```
┌─────────────────────────────────────────────────────────────────┐
│  Miles (train.py)                                                │
│                                                                  │
│  1. 启动 Ray                                                     │
│  2. 启动 Router (sglang_router)  →  监听 IP:30000                 │
│  3. 创建 SGLangEngine Ray Actor  →  每个 actor 拉起一个 SGLang 进程 │
│  4. SGLang 向 Router 注册: POST /add_worker?url=http://...       │
│  5. Rollout: Miles 向 Router 发 /generate 请求                   │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  Router (port 30000)                                             │
│  - 接收 /generate 请求                                          │
│  - 负载均衡到已注册的 SGLang worker                               │
│  - 转发请求、返回结果                                             │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│  SGLang Server (由 Miles 的 Ray Actor 拉起)                       │
│  - 实际跑推理                                                     │
│  - 每个 engine 可能占多卡 (tp_size)                               │
└─────────────────────────────────────────────────────────────────┘
```

**结论**：是 Miles 启动了 SGLang 进程，并通过 Router 作为入口。你只需要知道 **Router 的 IP + port**，就可以从任意终端对同一集群发请求。

---

## 你的请求走哪条路？

| 来源         | 请求路径                          |
|--------------|-----------------------------------|
| Miles 训练   | Miles → Router:30000/generate → SGLang |
| 你的测试脚本 | 你的终端 → Router:30000/generate → SGLang |

两者都打到同一个 Router，Router 会把请求转发到同一个 SGLang 池。所以你的请求和 Miles 的 rollout 请求**共享同一批 SGLang worker**。

---

## 排队与延迟

- **Router** 有请求队列，多个客户端会排队
- Miles 的 rollout 和你的测试脚本**共享队列**，会互相排队
- 影响：
  - 你的请求可能比「单独起 SGLang」时慢一些
  - Miles 的 rollout 也会因为你的请求而略慢
- 对**确定性验证**无影响：只是多了一些并发请求，不改变推理逻辑

---

## 这种「hack」的影响

| 方面         | 影响 |
|--------------|------|
| **正确性**   | 无。Router 和 SGLang 的 API 不变，结果一致。 |
| **性能**     | 有。请求共享队列，会有排队，略有延迟。 |
| **资源**     | 无额外占用。仍然用同一批 SGLang，不增加进程。 |
| **确定性**   | 无影响。你的请求和 Miles 的请求用同一套权重和配置。 |

**总结**：这是利用 Miles 已有组件的正常用法，不是侵入式 hack。只要知道 Router 的 `IP:port`，任何能发 HTTP 的客户端都可以用。

---

## Docker 下的网络

若 Miles 跑在 Docker 里：

- **容器内**：`localhost:30000` 或 `127.0.0.1:30000` 可访问 Router
- **宿主机**：需要端口映射（如 `-p 30000:30000`），用 `localhost:30000` 或宿主机 IP

两个终端都进同一容器时，用 `localhost` 即可。
